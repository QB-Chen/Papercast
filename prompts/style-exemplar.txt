10 月 27 号，OpenAI 和 Anthropic 分别发表了一篇论文。OpenAI 的论文标题是《The Exponential Time Hypothesis is False》，Anthropic 的论文标题是《A \(2^{o(n)}\) Time Algorithm for 3-SAT》。虽然标题不一样，但它们表达的是同一件事情。

ETH 翻译过来叫做指数时间假设（Exponential Time Hypothesis），它是计算复杂性理论中的一个重要猜想，而且和千禧年数学难题 P 是否等于 NP 密切相关。可以说，它是一个非常非常重要的基础性理论。

据 Anthropic 的统计，有 800 多篇论文的研究建立在 ETH 假设之上。虽然不像网上所说的那样，这些论文全都变成废纸了，但是确实会波及大量算法复杂度下界的研究。

不过我觉得更重要的是，ETH 这个假设是大多数科学家坚信成立的，而且人们尝试了几十年，仍然没有找到推翻它的方法。

像之前 AI 公布的一些数学成果，很多可能是：我知道这件事情是真的，但是我不知道怎么证明。AI 帮助我们找到了一种证明方法。

但这次有点不一样。它有点像是人类普遍认为正确无比的事情，甚至在此基础之上建立了庞大的学科体系，而作为根基的这样一个支柱性假说，竟然被 AI 证明是错误的。

假如现在有 A、B、C 三个员工要进行排班，但是老板有这么几个要求：

第一，至少有一个人值班。

第二，最多只能有两个人值班。

第三，A 不能单独值班，因为他太菜了。

那你想想看，要是你的话，你会怎么排呢？

当然了，你可以纯靠自己的脑子来硬想这个逻辑，然后给出排班方案。比如说，直接让 B 自己值班就好了。你可以看看是不是三条要求都满足。

当然了，有没有更科学的办法呢？

那我们可以这样，先把每一句人类说的话，翻译成格式比较固定的逻辑语言。

至少有一个人值班，那说得死板一点就是：A 值班，或者 B 值班，或者 C 值班。我们用这个符号 \(\lor\) 表示逻辑或。

最多只能有两个人值班，那换句话说就是，至少有一个人不值班。

那换成刚刚那种表述方式，就是 A 不值班，或者 B 不值班，或者 C 不值班。

我们用这个符号 \(\neg\) 表示逻辑非，在这里就是不值班的意思。

第三句话，A 不能单独值班，那我们也同样换一下。

也就是说，如果 A 来值班，那么 B 和 C 至少要有一个人也来。换成符号的话，就是：

\[
\neg A\lor B\lor C
\]

这里的 A、B、C 分别叫做布尔变量（Boolean Variable），取值分别是 1 或者 0，表示来或者不来。

那这些符号就可以变成一种数学计算了。

比如说，这个或就表示只要有一个是 1，最终的结果就是 1。

那这样我们可以把所有的结果都列出来，这个表就叫作真值表。

回到主线，这三条规则需要同时满足，也就是说，它们三个整体之间又有一个新的逻辑关系。

我们把这个符号叫作与，表示同时满足的意思。

那我们也列一个真值表，就是这个样子。

那我们最终无非就是问，有没有一种 A、B、C 的取值，能让这个 F 等于 1 呢？

这样我们就把一个自然语言描述的逻辑问题，转换成了一个纯粹的数学计算问题。

我们把这里的每个变量和它的否定叫作文字（Literal），变量之间用或连接起来，叫作一个子句（Clause）。所有的子句再用与连接起来，叫作一个合取范式，英文叫作 CNF（Conjunctive Normal Form）。

如果每个子句最多有三个文字，像我们这个问题就是这种特殊的情况，我们就叫作 3-CNF。

而判断一个 3-CNF 公式是否可能等于 1，这就叫作一个 3-SAT 问题。

在我们这个问题里面，就是说是否存在一种 A、B、C 的取值，使得这个 F 等于 1。

那对应到最初的那个场景，就是能不能找到一种排班组合，满足老板的各种要求。

如果今后你老板提出了一些无理的要求，而你又没有办法说服他的时候，你就可以把它转换成一个 3-SAT 问题，然后告诉他无解就好了。

那这个问题有什么比较好的解决办法吗？

你肯定也能想到了，最简单的就是把所有的情况全都列出来，暴力求解嘛。每一种情况都计算出结果，最终看看有没有等于 1 的值就行了。

那有没有比这个暴力求解更好的办法呢？

几十年来，人们发明了无数种算法，比暴力枚举的求解办法快得多，也聪明得多。

但是呢，ETH 假设告诉你，虽然有那么多花里胡哨的算法，但是本质上其实没有比暴力枚举好到哪去。它们仍然需要指数级别的时间复杂度。

当然，这里有一个稍微严格一点的版本，我们后面再说，别着急。

这个就是视频开头说的：这个假设持续了几十年，相当多的理论也建立在它之上，而且很多科学家坚信它是真的。

而今天呢，被 OpenAI 和 Anthropic 提出的新算法挑战了，我们找到了一个更快的算法。

在众多类型的问题当中，有一类问题叫作判定问题。

也就是说，判断一件事情是真的还是假的。

像我们刚刚那个排班问题，就是一个判定问题。

判定问题中有一类是不可判定问题，比如说经典的停机问题。那这里我们暂时不做讨论。

在这些可判定的问题当中，我们又发现，它们的困难程度好像不太一样。

比如说我给定一个集合，让你判断它里面是否有偶数，这个问题我们直觉上就感觉非常容易。

那我们把这类能够在多项式时间内找到答案的问题叫作 P 问题。

但是还有一类问题，比如说我们刚刚说的这个 3-SAT 问题就很难，好像除了暴力试遍所有的可能之外，找不到什么其他的办法。

但是它还有另外一个特点，就是假如有个人给你一种排班组合，说这种方案符合要求，我们能够快速地验证它是否真的符合要求。

那我们把这类能够在多项式时间内验证答案的问题叫作 NP 问题。

这种 NP 问题非常多，比如说旅行商问题。

它问的是：是否存在一条经过所有点、每个点不重复经过的路线，使得总长度小于某个数？

那求解这个问题呢，可能要试遍所有可能的路线。

但是假如你给出一条路线，让我验证，就非常非常容易了。

那这两类问题有什么关系呢？

显然，P 问题是包含在 NP 问题之内的。也就是说，能够快速给出答案的问题，也一定能够快速验证答案是否正确。

注意，这里并不是说给一个集合里的数，让你验证它是否是偶数。

那最终验证的仍然是这个集合是否存在偶数这个问题。只不过呢，我可以给你一个例子，让你更方便地验证这个问题。

但是既然你在没有例子的情况下，都能快速地判断有还是没有了，那在有例子的情况下，当然也一定能快速判断了。这就是显而易见的事情。

所以说，这就是为什么 P 问题是包含在 NP 问题之内的。

但是反过来，NP 问题也一定包含在 P 问题内吗？

也就是说，只要给出答案就能快速验证的问题，那是否也意味着在不给出答案的时候，也能快速解决它呢？

这就是经典的千禧年数学难题：P 是否等于 NP？

答案是什么？没人知道。

那 ETH 假设被推翻，和 P 是否等于 NP 这个问题又有什么关系呢？

要讲清楚这个问题，就不得不引入复杂度的概念了。

刚刚我们所描述的，都是用的比较模糊的词汇，什么很快、很慢、很容易、很困难，但是它们之间的程度又存在不同。

那要想比较这种不同程度的快和慢，就要想一个办法来量化它们。

比如说，刚刚我们想判断一个集合中是否有偶数。假如这个集合中有 N 个元素，那最坏的情况无非就是把所有的数据都看一遍嘛，那也就是 N。

那刚刚这个 3-SAT 问题看起来就很难。比如说我这种笨小孩，暂时只能想到暴力枚举的方式了。

那这种情况下呢，每个变量都有取 0 和取 1 两种情况，那么最终排列组合起来就一共有：

\[
2^n
\]

种可能。

也就是说，在最坏的情况下，需要尝试 \(2^n\) 种可能，才能判断出这个问题的答案。

那这里的 N 和 \(2^n\) 都是对输入规模的一个函数，我们就把 \(O(n)\) 和 \(O(2^n)\) 叫作这个算法的时间复杂度。

那之所以用大 O 括起来，是因为我们想忽略这里面一些常数项，或者严格点说，是用渐进上界来描述增长，并且忽略常数倍和较低阶项。

比如说 \(O(n)\)、\(O(2n)\) 或者 \(O(3n)\)，对我们来说都是一样的，它们就表示复杂度的增长是和输入规模呈线性关系的。

而 \(O(2^n)\) 则是呈指数关系的。

我们就只关注这个变化趋势的增长，而不是它绝对的量。

那如果我给这个增长趋势排个序的话，在数轴上大概是这个样子。

而我们刚刚描述的能够快速求解，这个快指的就是它的复杂度落在这个区间，我们管它叫作多项式时间内。

而刚刚说的非常难求解，准确来说，我们是想表达它的复杂度落在这里，也就是指数级的时间复杂度。

而它们的中间还有很多复杂度的趋势，我们可以统称为亚指数时间。

不过严格来说，多项式时间也属于一种特殊的亚指数时间。

那我们重新整理一下刚刚的描述。

我们说 P 问题属于能够快速解决的问题，其实准确点说，是我们能够找到多项式时间内解决它的算法，也就是落在这个区间内。

于是呢，人们想知道，能够快速验证的 NP 类问题，它们的解决算法的复杂度是否也能落在这个区间呢？

这就是一个悬而未决的问题。

而 ETH 假设说得更狠一些，它说的是 3-SAT 这个问题，不但找不到多项式时间内的解法，甚至连亚指数时间的解法都没有。

也就是说，不存在一个能够在 \(2^{o(n)}\) 时间内解决所有 3-SAT 实例的算法。

最终只能落在指数级这个区间内。

而后面我们会说，3-SAT 问题是一类 NP 完全问题。

也就是说，所有的 NP 问题都能在多项式时间内归约到一个 3-SAT 问题上。

那如果 3-SAT 问题找到了一个多项式时间内的解法，那就意味着所有的 NP 问题都可以找到多项式时间的解法，那也就证明了 P = NP。

所以说，3-SAT 这个问题为什么这么重要？ETH 这个假设为什么又说的是 3-SAT 问题？

就是因为它和 P 是否等于 NP 这个猜想有着这样千丝万缕的关系。

那 OpenAI 和 Anthropic 挑战的这个 ETH 假设，有没有达成这一目标呢？

也就是它们有没有证明 3-SAT 问题可以有多项式时间内的解法呢？

没有。

但是它们给 3-SAT 问题找到了一种亚指数时间的解法。

那相当于推翻了一个比 P 不等于 NP 更强的假设——ETH。

但是呢，对于 P 是否等于 NP 这个问题，并没有直接给出答案。

好了，那接下来又多出几个新问题了，我用大白话快速地说一下。

首先，为什么刚刚说的 3-SAT 问题可以代表所有的 NP 问题呢？

因为有一个叫作 Cook–Levin 定理的结果，证明了 SAT 是 NP 完全问题，而 3-SAT 也可以通过多项式时间归约证明为 NP 完全问题。

也就是说，假如你有一个 NP 问题，不知道怎么求解，那么有一种普适的办法，让你可以很快速地把它转换成一个 3-SAT 问题。

而 3-SAT 问题如果也能快速求解，那么就意味着你原来这个 NP 问题也能快速求解。

那像 3-SAT 这种能够让所有 NP 问题都归约过来的一种特殊的 NP 问题，我们就把它叫作 NP 完全问题。

3-SAT 就是一个 NP 完全问题，所以它非常重要。

第二个问题，这么多年了，3-SAT 问题就只能暴力求解吗？

不是的。

人们发明了无数种优化算法，有的算法已经在工程上非常有用了，但是在理论上，它依然属于指数级别的。

只不过是把指数前面的底数不断地变小。

那最新的记录呢，是今年 6 月发表的一篇论文，转换成底数的话就是这个数字，所以你也可以看到，ETH 这个假设被证伪，真的是在数学层面的降维打击。

第三个问题，3-SAT 问题既然能在亚指数时间内解决，那是否意味着所有的 NP 问题都能在亚指数时间内解决呢？

不是的。

这个也是网上很多出错的地方。

甚至有人说，ETH 假设被攻破了，我们的什么密码，还有隐私都荡然无存了。这个不是这样的。

NP 问题归约到 3-SAT 问题的时候，虽然是多项式时间内完成的，但是呢，它把问题的规模给扩大了。

比如说举个简单的例子，现在有一个 NP 问题，规模是 N，那转换为 3-SAT 问题后，规模可能变成了 \(N^2\)。

那即使 3-SAT 的时间复杂度是 \(2^{\sqrt n}\)，带回去呢，也又变成了：

\[
2^{\sqrt{N^2}}=2^N
\]

所以，3-SAT 的亚指数时间算法，并不意味着所有 NP 问题都能在亚指数时间内求解。

第四个问题，那 OpenAI 和 Anthropic 到底是用什么方法解决这个 3-SAT 问题的呢？

这个就比较难了，其实我也没太看懂。

下面呢，就只讲解一下我所理解的 OpenAI 论文中的解决思路。

那关于它的详细原理，就只能期待相关领域的大佬出个视频了。

首先，有一个特别反直觉的事情，就是原始的 3-SAT 问题，其实只需要判断一下是或否就可以了。

那 ETH 假设说的就是，单纯判断它需要的时间是指数级别的。

而 OpenAI 的方法竟然是直接计算出了一共有多少种情况。

也就是说，它把一个判定问题变成了一个更难的计数问题。

但是在这个更难的问题面前，它依然把时间复杂度给降下来了。

总体的思路就是，先把逻辑式转换成代数式，然后再把这个代数式转换成更方便分组、以减少计算次数的其他代数式。

然后再找到一种办法，能够通过计算这些代数式的值，来还原原代数式的值是多少。

简单说就是，原来有个公式不好算，然后我想办法给它转换成一个更好算的公式，然后呢，我再把这个更好算的公式的值给算出来了。

然后我还能找到一种办法，就是通过这些值，我能知道原来的这个公式的值是什么。

然后最终我再来乱七八糟地总结一下吧。

首先，一个最大的框架就是，我们想研究一类判定问题。

然后呢，判定问题当中有一类问题，就是能够以多项式时间内，比如快速找到答案的问题，我们叫作 P 问题。

然后还有的问题呢，就是如果给我一个答案，我能在多项式时间内快速验证的问题，叫作 NP 问题。

P 问题属于 NP 问题是非常显然的，就是我能快速找到答案，那我一定能够在给出答案之后快速验证。

但是 NP 问题是否属于 P 问题呢？

这个就是千禧年数学难题：P 是否等于 NP？

这个问题至今没有人能找到答案。

但是呢，这个猜想有点太强了，就是它想要的是 NP 问题同样也能在多项式时间内解决。

所以说，还有一个更强的假设叫作 ETH。

ETH 说的是，3-SAT 这个问题不存在亚指数时间的算法。

也就是说，它既不能在多项式时间内解决，也不能在亚指数时间内解决。

这个就比 P 不等于 NP 的那个结论更严格一些，就是说它不仅要求不能在多项式时间内解决，连亚指数时间都完成不了。

然后这个为什么跟 P 是否等于 NP 有关呢？

因为 3-SAT 问题是一类 NP 完全问题。

而 NP 完全问题指的是所有的 NP 问题都能在多项式时间内归约到一个 NP 完全问题。

所以说它是 NP 问题的一个代表。

如果你能把它攻破了，也就是说，如果你能证明它可以在多项式时间内解决，那么所有的 NP 问题就全都解决了，进而那个 P = NP 问题也就彻底解决了。

不过好在呢，OpenAI 和 Anthropic 提出了亚指数时间算法来解决这个 3-SAT 问题，而不是说直接找到了一个多项式时间内的算法。

如果是后者，直接找到了一个多项式时间算法的话，那 P = NP 问题就彻底解决了。

但是它们找到的是亚指数时间算法，而且这个亚指数时间算法也不能证明所有的 NP 问题都存在亚指数时间算法。

所以说，它影响的程度又更弱了一些。

当然，它也是一个非常非常多理论的支柱性问题。
